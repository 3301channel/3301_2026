# Git 核心常用命令超详细文档（通俗易懂版）

本文档整理开发中最常用的 6 条 Git 核心命令：**git status、git add、git commit \-m、git push、git pull、git checkout**，包含命令作用、语法、常用场景、通俗原理，同时搭配完整开发流程，适合新手入门、日常查阅。

## 一、Git 工作区域核心认知（必看）

理解三个区域，就能彻底搞懂所有命令逻辑：

1. **工作区**：本地电脑实际修改的代码文件

2. **暂存区**：临时存放待提交的修改（中转站）

3. **本地仓库**：本地保存的历史版本快照

4. **远程仓库**：GitHub / Gitee / 服务器云端代码仓库

核心流程：工作区修改 → 暂存区 → 本地仓库 → 远程仓库

## 二、六大核心命令详解

### 1\. git status（查看状态）

**作用**：查看当前代码仓库的全部状态，清晰区分文件是未修改、已修改、已暂存、未跟踪。

**输出标识含义**：

- 红色文件：工作区已修改、未执行 git add（未进暂存区）

- 绿色文件：已执行 git add（进入暂存区，等待提交）

- untracked：全新文件，Git 未跟踪

**基础用法**：

```bash
git status
```

**使用场景**：每次修改代码后、提交前，查看自己改了哪些文件，确认无误再提交。

### 2\. git add（加入暂存区）

**作用**：将工作区的代码修改，添加到暂存区，标记为「待提交版本」，是 commit 提交的前置操作。

**常用语法（开发高频）**：

```bash
# 单个文件加入暂存
git add 文件名

# 所有修改、新增的文件全部加入暂存（日常最常用）
git add .

# 仅提交已有文件的修改，不提交新增的陌生文件（更安全）
git add -u
```

**通俗理解**：相当于「选中要保存的修改内容」，告诉 Git 这些改动需要记录版本。

### 3\. git commit \-m（生成本地版本）

**作用**：将暂存区的所有改动，打包生成一个**本地版本快照**，永久记录到本地仓库，形成可追溯的版本记录。

**语法说明**：\-m 代表 message，后面必须跟本次修改的备注说明，规范开发追溯。

**基础用法**：

```bash
git commit -m "本次修改说明，例如：修复登录弹窗bug、新增列表查询功能"
```

**重要注意**：commit 仅保存到**本地仓库**，不会同步到云端远程仓库。

### 4\. git push（推送到远程仓库）

**作用**：将本地仓库已生成的 commit 版本，同步上传到 GitHub/Gitee 等远程仓库，实现代码云端备份、团队同步。

**常用语法**：

```bash
# 标准写法：推送到远程 origin 的 main/master 分支
git push origin main

# 配置默认分支后，可直接简写
git push
```

**使用场景**：本地代码写完、自测无误后，上传云端同步代码。

### 5\. git pull（拉取远程最新代码）

**作用**：拉取远程仓库的最新代码，自动合并到本地当前分支，保证本地代码和云端一致。

**原理等价**：git fetch（下载远程代码） \+ git merge（合并代码）

**常用语法**：

```bash
# 标准拉取最新代码
git pull origin main

# 简写拉取
git pull
```

**强制规范**：每天开发前、提交代码前，必须先 pull，避免多人开发代码冲突。

### 6\. git checkout（切换分支 / 撤销修改）

该命令有两大核心用途：**分支操作**、**撤销本地未提交修改**

**1）分支操作（最常用）**

```bash
# 切换到已存在的 dev 分支
git checkout dev

# 创建新分支 feature 并直接切换过去（高频开发命令）
git checkout -b feature
```

**2）撤销本地未提交修改（急救命令）**

```bash
# 撤销单个文件的所有未 add 修改
git checkout 文件名

# 撤销当前目录所有未 add 的修改，恢复到原始状态（谨慎使用）
git checkout .
```

**注意**：仅能撤销**工作区未暂存、未提交**的修改，已 add、已 commit 的改动无法用此命令撤销。

## 三、完整标准开发流程（串联所有命令）

日常单人/团队开发标准步骤，直接照着执行即可：

```bash
# 1. 开发前先拉取远程最新代码（防止冲突）
git pull

# 2. 本地修改代码、新增功能、修复bug

# 3. 查看修改文件，确认改动无误
git status

# 4. 所有改动加入暂存区
git add .

# 5. 生成本地版本，填写修改备注
git commit -m "完成xx功能/修复xx问题"

# 6. 推送本地版本到远程仓库
git push
```
