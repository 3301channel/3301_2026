# PDF 水印接口文档

服务地址默认 `http://127.0.0.1:8000`，Swagger 交互文档位于 `/docs`。

---

## 1. 接口总览

| 序号  | 方法       | 路径                                         | 用途                              |
| --- | -------- | ------------------------------------------ | ------------------------------- |
| 1   | `POST`   | `/api/v1/watermark/tasks`                  | 创建水印任务（注入或检测），必填 `operation` 字段 |
| 2   | `GET`    | `/api/v1/watermark/tasks/{task_id}/result` | 查询任务状态，或下载任务产物                  |
| 3   | `DELETE` | `/api/v1/watermark/tasks/{task_id}`        | 删除已完成/失败的任务及其文件                 |

所有响应统一为 `{"code": 业务码, "msg": 消息, "data": 数据}` 结构。

---

## 2. operation 字段

`operation` 是创建任务接口（`POST /api/v1/watermark/tasks`）**必填**的表单字段，告诉服务端这个任务要做什么。

### 2.1 取值

| 取值       | 含义                         | 输入文件                          | 输出              |
| -------- | -------------------------- | ----------------------------- | --------------- |
| `embed`  | **注入水印**：给 PDF 每页写入规则网格水印  | 仅接受 `.pdf`                    | 注入水印后的新 PDF     |
| `detect` | **检测水印**：判断照片中的打印件是否含有网格水印 | 仅接受 `.jpg` / `.jpeg` / `.png` | 检测结论 + 诊断报告 PNG |

### 2.2 operation

选定 `operation` 后，服务端以下全部行为随之固定：

|                | `embed`嵌入                                                   | `detect`提取                                                                               |
| -------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 上传文件类型         | PDF（解析校验：可打开、未加密、至少 1 页）                                    | 照片                                                                                       |
| 水印参数           | 固定 `grid-v4-balanced`（18 LPI、±45°、0.45pt、灰 0.88）            | 不适用（服务端已按同一配置检测）                                                                         |
| 处理内容           | 每页底层写入矢量交叉网格，不改变页数/尺寸/文字                                    | 质量门禁 → ROI 裁剪 → CLAHE → 局部周期与 FFT 证据聚合                                                   |
| 完成后的 `results` | `file_name`、`page_count`、`watermark_version`、`download_url` | `embedded`、`allow_stamp`、`status`、`score`、`threshold`、`calibration_version`、`report_url` |
| 可下载的产物         | `?artifact=output`（水印 PDF）                                  | `?artifact=report`（诊断 PNG）                                                               |
| 业务用途           | 用印前给合同 PDF 打水印                                              | 用印前验证纸质打印件是否来自已加水印 PDF                                                                   |

### 2.3 如何选择

- 手上是**电子 PDF**，需要打水印后给别人打印 → `operation=embed`
- 手上是**打印件的照片**，需要判断它是否带水印 → `operation=detect`
- 两者输入文件不同：`embed` 传 PDF，`detect` 传照片，**传错类型会被拒绝**（HTTP 400，业务码 `40001`）

### 2.4 选错 operation 的后果

| 情况                                 | 结果                            |
| ---------------------------------- | ----------------------------- |
| `operation=embed` 但上传 `.jpg`       | 400：embed 只接受 PDF             |
| `operation=detect` 但上传 `.pdf`      | 400：detect 只接受 JPG/JPEG/PNG   |
| 上传文件类型正确但内容损坏                      | 400：无法解析                      |
| 用 `detect` 任务请求 `?artifact=output` | 400：产物与任务不匹配（detect 没有输出 PDF） |
| 用 `embed` 任务请求 `?artifact=report`  | 400：产物与任务不匹配（embed 没有检测报告）    |

> 注意：`operation` 一旦提交不可修改。提交前请确认类型正确。

## 3. 接口 1：创建任务

```
POST /api/v1/watermark/tasks
Content-Type: multipart/form-data
```

### 3.1 请求字段

| 字段          | 类型     | 必填  | 说明                        |
| ----------- | ------ | --- | ------------------------- |
| `operation` | string | 是   | `embed` 或 `detect`，见第 2 节 |
| `file`      | file   | 是   | 待处理文件，类型取决于 `operation`   |

单文件最大 100 MiB。

### 3.2 响应（HTTP 202）

```json
{
  "code": 200,
  "msg": "Task submitted successfully",
  "data": {
    "task_id": "335cb9ef4530499bb95b3a1c923421f0",
    "operation": "embed",
    "file_name": "document1_v8.pdf",
    "status": "pending",
    "queued_ahead": 0,
    "created_at": "2026-08-04T01:10:50.241776+00:00",
    "started_at": null,
    "completed_at": null,
    "error": null,
    "results": null,
    "status_url": "http://127.0.0.1:8000/api/v1/watermark/tasks/335cb9ef4530499bb95b3a1c923421f0/result",
    "result_url": "http://127.0.0.1:8000/api/v1/watermark/tasks/335cb9ef4530499bb95b3a1c923421f0/result"
  }
}
```

保存 `task_id`，后续查询、下载、删除都依赖它。

## 4. 接口 2：查询结果 / 下载产物

```
GET /api/v1/watermark/tasks/{task_id}/result
GET /api/v1/watermark/tasks/{task_id}/result?artifact=output
GET /api/v1/watermark/tasks/{task_id}/result?artifact=report
```

### 4.1 查询状态（不传 artifact）

| task 状态                  | HTTP | 说明                                |
| ------------------------ | ---- | --------------------------------- |
| `pending` / `processing` | 202  | 仍在处理，继续轮询                         |
| `completed`              | 200  | 处理完成，`results` 携带结果和下载地址          |
| `failed`                 | 200  | 处理失败，`results` 为 null，业务码 `50002` |

`embed` 完成后 `results` 示例：

```json
"results": {
  "file_name": "document1_v8_watermarked.pdf",
  "page_count": 1,
  "watermark_version": "grid-v4-balanced",
  "download_url": "http://127.0.0.1:8000/api/v1/watermark/tasks/{task_id}/result?artifact=output"
}
```

`detect` 完成后 `results` 示例：

```json
"results": {
  "embedded": true,
  "allow_stamp": true,
  "status": "MARKED",
  "score": 0.2451,
  "threshold": 0.12,
  "calibration_version": "grid-v4-balanced-local-development",
  "report_url": "http://127.0.0.1:8000/api/v1/watermark/tasks/{task_id}/result?artifact=report"
}
```

`detect` 的三个状态(status字段）：`MARKED`（有水印，允许盖章）、`ORIGINAL`（无水印，拒绝盖章）、`INCONCLUSIVE`（照片质量不足，拒绝盖章并要求重拍）。仅 `MARKED` 时 `embedded` 与 `allow_stamp` 为 `true`。

### 4.2 下载产物（传 artifact）

| artifact | 适用任务       | 返回                                      |
| -------- | ---------- | --------------------------------------- |
| `output` | 仅 `embed`  | 水印 PDF（`application/pdf`，attachment 下载） |
| `report` | 仅 `detect` | 诊断报告 PNG（`image/png`，inline 预览）         |

任务未完成时请求产物返回 409；产物与任务类型不匹配返回 400；产物文件缺失返回 404。

## 5. 接口 3：删除任务

```
DELETE /api/v1/watermark/tasks/{task_id}
```

| 情况          | HTTP |
| ----------- | ---- |
| 删除成功（任务已终态） | 200  |
| 任务仍在处理中     | 409  |
| 任务不存在       | 404  |

## 6. 公共字段字典

任务 `data` 中的字段：

| 字段                                           | 类型             | 说明                                                |
| -------------------------------------------- | -------------- | ------------------------------------------------- |
| `task_id`                                    | string         | 32 位十六进制任务 ID                                     |
| `operation`                                  | string         | `embed` 或 `detect`                                |
| `file_name`                                  | string         | 上传的原始文件名（仅展示用途）                                   |
| `status`                                     | string         | `pending` / `processing` / `completed` / `failed` |
| `queued_ahead`                               | number         | 排队在该任务之前的任务数（当前并发为 1，通常为 0）                       |
| `created_at` / `started_at` / `completed_at` | string         | UTC 时间戳，未发生为 null                                 |
| `error`                                      | string \| null | 失败原因（不暴露内部路径）                                     |
| `results`                                    | object \| null | 结果数据，见第 4 节                                       |

## 7. status 字段的写入规则

文档中有两个 `status` 字段，写入规则完全不同，分别说明。

### 7.1 任务级 status（`data.status`）

任务级状态由服务端任务执行器写入，客户端只能读取、不可修改。

| 时机 | 写入状态 | 触发条件 |
| --- | --- | --- |
| 任务登记 | `pending` | 上传校验通过，任务创建并排队 |
| worker 开始 | `running`（对外显示 `processing`） | 线程池取出任务开始执行 |
| worker 正常返回 | `completed` | 算法执行成功 **且** 产物文件存在并通过安全检查 |
| worker 抛出异常 | `failed` | 处理过程中任何未捕获异常 |
| 产物异常 | `failed` | 算法返回但产物缺失、为符号链接或不在 outputs 目录内 |

关键规则：

1. **对外永不显示 `running`**：内部 `running` 在 JSON 响应中一律映射为 `processing`，客户端只会看到 `pending` / `processing` / `completed` / `failed` 四种。
2. **`completed` 是双条件**：算法成功 **且** 产物通过安全检查（普通文件、位于任务 outputs 目录内、非符号链接），两者都满足才写 `completed`。
3. **终态不可逆**：到 `completed` 或 `failed` 后状态不再变化，可安全 `DELETE`。
4. **取消即消失**：客户端中途断开（请求被取消）时，任务被回滚并从索引移除，查询返回 404，而不是 `failed`。
5. **原子写入**：`status` 与 `completed_at`、`error` 在同一次内部更新中同时写入。

### 7.2 检测结果 status（`results.status`）

仅 `detect` 任务在完成后写入 `results.status`，由 `local_service.classify_grid_photo` 决定，三个取值：

| status | 含义 | `embedded` / `allow_stamp` |
| --- | --- | --- |
| `MARKED` | 照片含有水印证据，可信 | `true` / `true` |
| `ORIGINAL` | 照片未检出或证据不达阈值 | `false` / `false` |
| `INCONCLUSIVE` | 照片质量不足或证据未达门槛 | `false` / `false` |

判定流程（按顺序）：

1. **质量门禁**：照片短边 < `min_short_edge`（900 px）或清晰度 < `min_sharpness`（12.0）或对比度 < `min_contrast`（20.0）→ 直接 `INCONCLUSIVE`。
2. **局部周期检测**：ROI 裁剪 + CLAHE + 空间自相关 + FFT 匹配，得到 `positive_blocks`、`positive_ratio`、`spatial_cells`、`score`。
3. **硬门槛**：`valid_blocks < min_positive_blocks`（2）→ `INCONCLUSIVE`。
4. **终判**：四项指标全部达标（`positive_blocks ≥ 2` 且 `positive_ratio ≥ 0.002` 且 `spatial_cells ≥ 2` 且 `score ≥ decision_threshold`）→ `MARKED`；否则 → `ORIGINAL`。

关键规则：

1. **不可改**：客户端无法修改；阈值由服务端固定，不随单张照片调整。
2. **联动字段**：`results.embedded` 与 `results.allow_stamp` 与 `results.status == "MARKED"` 联动，三者恒一致（详见 7.3）。
3. **当前标定**（`grid-v4-balanced-local-development`）：
   - `decision_threshold = 0.12`
   - `min_positive_blocks = 2`
   - `min_positive_ratio = 0.002`
   - `min_spatial_cells = 2`
   - 状态为 `provisional`（开发标定，未用独立真实数据集正式批准）。
4. **示例**：截图示例 `score=0.2451 ≥ 0.12` → `MARKED`，`embedded=true`，`allow_stamp=true`。
5. **离线判定**：所有计算在服务端本地完成，不调用任何外部网络/模型/启发式调整。

### 7.3 嵌入判定字段（`results.embedded` 与 `results.allow_stamp`）

仅 `detect` 任务在完成后写入这两个布尔字段，由 `_run_detect` 在 `results.status` 写定的同一次更新中同步落入。

| 字段 | 类型 | 与 status 的关系 |
| --- | --- | --- |
| `results.embedded` | bool | `== (results.status == "MARKED")` |
| `results.allow_stamp` | bool | `== (results.status == "MARKED")` |

取值矩阵（由同一个 `marked` 局部变量决定，写入时同步）：

| `results.status` | `embedded` | `allow_stamp` |
| --- | --- | --- |
| `MARKED` | `true` | `true` |
| `ORIGINAL` | `false` | `false` |
| `INCONCLUSIVE` | `false` | `false` |

关键规则：

1. **不可改**：客户端无法修改；服务端在任务完成时一次性写入。
2. **恒同步**：两个字段在服务端代码中共享同一个 `marked` 表达式（`result.status == "MARKED"`），无法只让其中一个为 `true`。
3. **业务语义**：当前两者计算公式相同，但保留独立字段——`embedded` 表达"模型是否识别为水印"，`allow_stamp` 表达"系统是否允许盖章"，未来策略分化时两者可独立变化。
4. **联动决策**：用印系统读取 `allow_stamp`；盖戳流程约定仅在 `allow_stamp=true` 时执行，`false` 一律拒绝盖章。

## 8. HTTP 状态码与业务码

| HTTP | 业务码   | 含义                       |
| ---- | ----- | ------------------------ |
| 202  | 200   | 任务已提交，正在异步处理             |
| 200  | 200   | 查询/删除成功                  |
| 200  | 50002 | 任务处理失败                   |
| 400  | 40001 | 上传内容或参数无效（类型不匹配、文件损坏、超限） |
| 400  | 40002 | 制品类型无效或与任务不匹配            |
| 404  | 40401 | 任务不存在                    |
| 404  | 40402 | 制品不存在                    |
| 409  | 40901 | 任务未完成或正在被读取              |
| 422  | —     | 表单字段校验失败                 |
| 500  | 50001 | 任务上传保存失败                 |

## 9. 完整调用示例

### 9.1 embed：注入水印并下载

```powershell
# 1. 创建嵌入任务
$taskId = (curl.exe -s -X POST "http://127.0.0.1:8000/api/v1/watermark/tasks" `
  -F "operation=embed" `
  -F "file=@C:\work\contract.pdf;type=application/pdf" |
  ConvertFrom-Json).data.task_id

# 2. 轮询直到 completed
do {
  $r = curl.exe -s "http://127.0.0.1:8000/api/v1/watermark/tasks/$taskId/result" | ConvertFrom-Json
  Start-Sleep -Seconds 1
} while ($r.data.status -in @("pending", "processing"))

# 3. 下载水印 PDF
curl.exe -o .\contract_watermarked.pdf `
  "http://127.0.0.1:8000/api/v1/watermark/tasks/$taskId/result?artifact=output"
```

### 9.2 detect：检测照片并取结论

```powershell
$taskId = (curl.exe -s -X POST "http://127.0.0.1:8000/api/v1/watermark/tasks" `
  -F "operation=detect" `
  -F "file=@C:\work\printed-page.jpg;type=image/jpeg" |
  ConvertFrom-Json).data.task_id

do {
  $r = curl.exe -s "http://127.0.0.1:8000/api/v1/watermark/tasks/$taskId/result" | ConvertFrom-Json
  Start-Sleep -Seconds 1
} while ($r.data.status -in @("pending", "processing"))

$r.data.results.status   # MARKED / ORIGINAL / INCONCLUSIVE
$r.data.results.allow_stamp  # 仅 MARKED 为 true
```

## 10. Swagger 使用说明

启动服务后访问 `http://127.0.0.1:8000/docs`：

1. **创建任务**：展开 `POST /api/v1/watermark/tasks` → Try it out → `operation` 下拉选择 `embed` 或 `detect` → 上传文件 → Execute。
2. **查询/下载**：展开 `GET .../result` → Try it out → 填 `task_id`；下载时 `artifact` 填 `output`（embed）或 `report`（detect）→ Execute，文件类响应旁出现 Download 按钮。
3. **删除**：展开 `DELETE ...` → Try it out → 填 `task_id` → Execute。

---

## 11. 使用注意事项

- 服务**无内置鉴权**，`0.0.0.0` 绑定会暴露所有网卡，须部署在受控网关/反向代理之后。
- 任务索引保存在进程内存中，**服务重启后旧 task_id 无法查询/下载/删除**（磁盘文件仍在）。
- 检测阈值为开发标定（`provisional`），正式生产前需用与目标打印机/相机一致的正负样本集重新标定。
- 上传的 PDF 会逐页写入水印，页数、页面尺寸、旋转和可提取文字保持不变。
